## Introduction

Microsoft has expanded its Zero Trust for AI strategy by updating the Zero Trust Assessment tool and the Zero Trust Workshop to include a dedicated AI pillar and DevSecOps guidance. The changes introduce new checks, implementation tasks, and a framework for treating AI memory as a governed security boundary.

## What happened

- Microsoft updated its Zero Trust Assessment and Zero Trust Workshop to support secure AI adoption and to translate zero trust principles into developer-focused controls and CI/CD guidance.
- The Zero Trust Assessment now covers an AI pillar alongside identity, devices, data, network, infrastructure, and security operations.
- The Zero Trust Workshop added a DevSecOps pillar and uses the Microsoft AI Memory framework to improve AI-related controls and roadmapping.

## Key facts

- Zero Trust Assessment is a free tool that automatically evaluates an organization’s Microsoft security configuration against zero trust best practices, identifies weaknesses, and recommends improvements.
- The Assessment helps establish a baseline, measure progress, and identify gaps across traditional and AI-powered environments.
- The Assessment now covers seven pillars: identity, devices, data, network, infrastructure, security operations, and AI.
- The AI pillar introduces zero trust checks specifically for secure AI adoption.
- Enhanced Assessment reports provide prioritized recommendations and high-level summaries of risks, progress, and recommended actions, organized into a roadmap of immediate, mid-term, and longer-term priorities.
- The Zero Trust Workshop adds DevSecOps guidance mapped into 15 control groups and 91 tasks for development teams, CI/CD, source repositories, dependencies, artifacts, and infrastructure as code.
- The Workshop applies the Microsoft AI Memory framework, treating memory as a governed security boundary with clear intent, provenance, lifecycle visibility, and user control.
- Workshop tasks are organized into First, Then, Next stages to implement foundational controls before more mature measures.
- The DevSecOps pillar demonstrates how strengthening software development security supports identity, infrastructure, and security operations.
- Four AI-assisted development focus areas in the guidance: controlling AI-generated code, allowing only approved AI tools, protecting sensitive data, and securing the AI software supply chain.
- Microsoft published implementation guidance covering limiting AI agent access, protecting source code, securing AI memory, strengthening SDLC security, and secure software development governance.
- The Workshop process uses the Zero Trust Assessment to establish a baseline and yields a 12- to 24-month roadmap through a facilitated workshop.

## Impact

- Organizations using Microsoft security tooling can now assess AI-specific risks alongside traditional security controls via the expanded Zero Trust Assessment.
- Development teams receive prescriptive DevSecOps tasks (15 control groups, 91 tasks) to help integrate zero trust principles into CI/CD, repositories, dependency and artifact management, and infrastructure-as-code.
- The Microsoft AI Memory framework and associated guidance aim to provide governance and user control over AI memory components, making memory an explicit security boundary to manage intent, provenance, lifecycle, and access.

## Technical context

- The Update extends the established Zero Trust model to explicitly include AI-related controls and developer workflows. The Assessment’s seven pillars now include AI checks that complement identity, devices, data, network, infrastructure, and security operations.
- The DevSecOps pillar breaks down implementation into actionable tasks and control groups for software development lifecycles, emphasizing foundational controls first (First, Then, Next).
- The Microsoft AI Memory framework is a central piece of the Workshop improvements; it frames memory as a governed boundary with requirements for intent, provenance, lifecycle visibility, and user control.
- Four practical focus areas for AI-assisted development in the guidance are: (1) controlling AI-generated code, (2) allowing only approved AI tools, (3) protecting sensitive data, and (4) securing the AI software supply chain.
